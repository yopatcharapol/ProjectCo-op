## 1. วัตถุประสงค์ของการทดลอง (Objectives)
1. **พิสูจน์สมมติฐานหลักของโครงงาน (Core Research Paradigm):** ยืนยันว่าโทรศัพท์มือถือที่ **"ปิด Hotspot และไม่ได้เชื่อมต่ออินเทอร์เน็ตใดๆ"** จะยังคงแผ่คลื่น Probe Request ออกมาในอากาศให้ ESP32 ดักฟังได้จริง 100%
2. **ศึกษาพฤติกรรม Doze Mode vs Motion Trigger:** พิสูจน์ผลกระทบของการเคลื่อนไหวต่อความถี่ในการยิงแพ็กเก็ต (โทรศัพท์อยู่นิ่ง vs โทรศัพท์ถูกเขย่า/เคลื่อนที่)
3. **ตรวจสอบกลไก MAC Randomization และ Sequence Number:** วิเคราะห์การสุ่ม MAC และตัวนับลำดับเฟรมในระดับฮาร์ดแวร์

## 3. การค้นพบทางวิศวกรรมที่สำคัญ (Key Engineering Insights)

### 🌟 ข้อค้นพบที่ 1: เซนเซอร์ตรวจจับความเคลื่อนไหว (Accelerometer / Sensor Hub) ปลุก Wi-Fi จริง
* เมื่อโทรศัพท์วางอยู่นิ่งๆ (เคส B) ระบบ OS จะหน่วงเวลาการค้นหา Wi-Fi ทิ้งช่วงกว้าง (ในผลการทดลองทิ้งช่วงถึง **21.6 วินาที**)
* แต่ทันทีที่มีการ **"ขยับตัว หรือเขย่าเครื่องเบาๆ"** (เคส C) วงจรตรวจจับการเคลื่อนไหว (CoreMotion / Sensor Hub) จะสั่งปลุกชิป Wi-Fi ส่งคลื่นออกมาเป็นชุดใหญ่ (Burst 8 แพ็กเก็ตใน 0.48 วินาที)
* **ความหมายเชิงยุทธศาสตร์การกู้ภัย (Search and Rescue):** คนหลงป่าที่กำลังเดิน ตะเกียกตะกาย หรือขยับตัวในป่า จะทำให้โทรศัพท์ยิงคลื่นออกมาถี่มากและเป็นกลุ่มก้อน ทำให้เสา Checkpoint ตรวจจับได้ทันทีโดยไม่ต้องรอรอบ Doze Mode!

---

### 🌟 ข้อค้นพบที่ 2: ปริศนา "Wildcard แปลกๆ" คืออะไร?
ในผลการทดลอง เกือบทุกแพ็กเก็ตขึ้นคำว่า `"Wildcard"`:
* **ความหมาย:** Wildcard Probe Request คือแพ็กเก็ตที่ **SSID มีความยาวเป็น 0 (ช่องว่างเปล่า)** 
* **ทำไมมือถือถึงส่ง Wildcard?:** เป็นระบบความปลอดภัย (Privacy & Anti-Tracking) ของ iOS และ Android ยุคใหม่ ซึ่งจะไม่ตะโกนบอกชื่อ Wi-Fi ที่เคยต่อ (เพื่อไม่ให้ใครรู้ว่าเราเคยไปพักโรงแรมไหนหรือบ้านอยู่ที่ไหน) แต่จะส่งคำถามกว้างๆ ออกไปว่า *"แถวนี้มี Access Point ใดๆ อยู่บ้างไหม? ขอให้ตอบกลับมา"* 

---

### 🌟 ข้อค้นพบที่ 3: จับโป๊ะบ้านใกล้เรือนเคียง! (Directed Probe Request)
ในเคส C บรรทัดที่ 11:
```csv
CSV,44648,11,6,-95,2866,B0:E4:5C:74:A8:D2,REAL,"Thaweeyont-PO(5G)"
```
* นี่คืออุปกรณ์ที่อยู่ไกลออกไป (RSSI = -95 dBm) ซึ่งไม่ได้ส่งแบบ Wildcard แต่ส่งแบบ **Directed Probe Request**
* ตัวเครื่องตะโกนถามหาชื่อ Wi-Fi เฉพาะเจาะจงว่า **`"Thaweeyont-PO(5G)"`** และแถมยังใช้ **MAC จริง (`REAL` - OUI: B0:E4:5C)** ซึ่งอาจเป็นสมาร์ตโฟนรุ่นเก่า แล็ปท็อป หรืออุปกรณ์ IoT แถวบ้านที่พยายามหาเราเตอร์ประจำของมัน

---

### 🌟 ข้อค้นพบที่ 4: ลำดับ Sequence Number ต่อเนื่อง แม้ MAC จะถูกสุ่ม!
สังเกตเครื่องเป้าหมาย `D6:6E:EA:14:9B:15` (`RANDOM`):
* ในเคส C ช่วงยิงกระตุก 8 แพ็กเก็ต: `SEQ: 1906, 1907, 1909, 1914, 1916, 1917, 1919, 1925`
* ตัวเลข Sequence Control ของชิปวิทยุจะ **นับบวกเพิ่มขึ้นเรื่อยๆ เสมอ**
* สิ่งนี้พิสูจน์ทฤษฎีในเอกสารสเปก `SPEC-08` ของเราว่า **เราสามารถใช้ค่า Slope ของ Sequence Number เพื่อจับกลุ่ม (Clustering) ว่าแพ็กเก็ตเหล่านี้มาจากโทรศัพท์เครื่องเดียวกันได้ แม้ระบบปฏิบัติการจะเปลี่ยน MAC สุ่มก็ตาม!**

---

### 🌟 ข้อค้นพบที่ 5: การแยกแยะระยะใกล้-ไกลด้วย RSSI สำหรับเสา Checkpoint
ระดับความแรงสัญญาณที่ดักจับได้แบ่งออกเป็น 3 โซนชัดเจน:
1. **โซนในมือ / บนโต๊ะ (Checkpoint In-Zone):** `RSSI = -18 ถึง -30 dBm` (เครื่องเป้าหมายของผู้ทดลอง)
2. **โซนในห้องเดียวกัน (Room-Zone):** `RSSI = -37 ถึง -48 dBm` (เครื่อง `C0:A5:E8:...` MAC จริง)
3. **โซนภายนอกห้อง / เพื่อนบ้าน (Out-of-Zone Noise):** `RSSI = -93 ถึง -98 dBm` (เครื่อง `6E:8D:...`, `CE:4E:...`, `AA:EE:...`)

> 🎯 **บทสรุปสำหรับ Checkpoint:** หากเราตั้งเสา Checkpoint ในป่า แล้วใส่เงื่อนไขง่ายๆ ในโค้ดว่า:
> ```cpp
> if (rssi >= -65) {
>     triggerCheckpointAlert(); // มีคนเดินเข้ามารัศมี 15-20 เมตรของเสาแล้ว!
> }
> ```
> ระบบจะตัดสัญญาณรบกวนที่อยู่ไกลลิบออกไปได้ทันที 100% และแจ้งเตือนเฉพาะคนที่ก้าวเข้าสู่วง Checkpoint ของเราเท่านั้น!
